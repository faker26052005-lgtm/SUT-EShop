3. Phân Tích Chuyên Sâu: Functional API Testing vs Contract Testing

Vấn đề cốt lõi: Tại sao kiểm thử chức năng truyền thống (Postman/Newman) vẫn báo HTTP 200 OK nhưng ứng dụng di động khách hàng lại bị sập?

Khi lập trình viên Backend đổi tên trường price thành unit_price hoặc format thành chuỗi '30.000.000 ₫':

  • Postman / Newman: Gửi request và nhận về status 200 OK. Nếu test script chỉ kiểm tra mã HTTP status, Newman sẽ báo PASS và bản build được phép deploy!
  • Mobile App (EShopMobile): Mã nguồn gọi product.price sẽ nhận về undefined. Khi thực hiện phép nhân tính tiền giỏ hàng (price * quantity), ứng dụng gặp lỗi NaN hoặc ném ngoại lệ Runtime Error làm văng ứng dụng.
  • Pact JS (CDCT): Đóng vai trò như một Deployment Gate. Trong CI/CD của Backend, Pact Verifier lập tức so sánh response với bản hợp đồng do Mobile quy định, phát hiện thiếu key price và đánh FAIL bản build ngay tại chỗ!

4. Bảng Kết Quả Thực Thi Kịch Bản Pact C3

Giai đoạn Hành vi Provider Kỳ vọng Kết quả thực tế Đánh giá
Pha 1: Baseline Provider trả về đầy đủ các trường (price: 30000000 kiểu Integer) PASS 100% PASS ĐẠT (Hợp đồng toàn vẹn)
Pha 2A: Rename Key Đổi trường price ➔ unit_price (HTTP 200 OK) BLOCK (FAIL) BLOCKED ĐẠT (Bắt đúng lỗi thiếu key price)
Pha 2B: Type Mismatch Trả về chuỗi format tiền tệ '30.000.000 ₫' thay vì số nguyên BLOCK (FAIL) BLOCKED ĐẠT (Bắt đúng lỗi sai kiểu dữ liệu)
Pha 3: Rollback Hoàn nguyên mã nguồn Provider về trạng thái chuẩn mực ban đầu PASS 100% PASS ĐẠT (Hệ thống an toàn trở lại)
